Why Enrai

Built for people who are shipping.

A thin layer in front of several model providers. You keep your SDK, your prompts and your existing code — Enrai handles the routing.

⌁

OpenAI-compatible endpoints

POST /v1/chat/completions and GET /v1/models follow the OpenAI shape, so existing SDKs and tools work by changing the base URL.

⇉

Automatic provider failover

Every model name is a server-managed combo. When one provider fails, the request is routed to another member of the combo instead of returning an empty answer.

≡

SSE streaming

Send "stream": true and read answer chunks in real time in the OpenAI chunk format, terminated by [DONE].

◎

One key, many models

No per-provider accounts. One key from the dashboard unlocks every available model, and /v1/models shows what is live right now.

⏱

Published limits

20 chat requests per minute (burst 5) and 60 model-list requests per minute, per key. The numbers are written down instead of appearing as a mysterious 429.

⌘

Fits your stack

curl, Node.js, Python, PHP, or any client that speaks the OpenAI format — including editors and tools that accept a custom base URL.

FAQ

The questions people actually ask.

Is it really free?

Yes. During public beta there is a free tier with no credit card: one key, every available model, with limits published on the pricing page.

Do I have to rewrite my application?

No. If you already use the OpenAI SDK or an OpenAI-compatible client, just change the base URL to https://enrai.web.id/v1 and the API key. Request, payload and response shapes stay the same.

What happens when a provider is down?

Every model name is a combo of several providers. A failed request is retried against another member of the combo. If every attempt comes back empty, you receive a 502 with an error message instead of a blank answer.

Is streaming supported?

Yes — "stream": true returns Server-Sent Events in the OpenAI chunk format, terminated by [DONE].

What about my data?

Prompts are forwarded to the upstream provider serving that request; see the privacy policy and terms of service. Do not send secrets you would not send to a third-party API.

Is it production-ready?

It is in public beta. Suitable for prototypes, side projects and internal tools — keep a second provider for anything that must not fail.
